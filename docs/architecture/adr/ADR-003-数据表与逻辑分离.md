## 1. 背景

### 1.1 这是本项目投入产出比最高的一条 ADR

策划测算：**79% 的开发工作是"填数据表"**（`system-breakdown.md` §0：沿用 37% + 改造 39%，46 个系统中 35 个的工作量就是"改内容不改结构"）。

具体规模：

| 数据表 | MVP | V1 | 前作实测行数 |
|---|---|---|---|
| `MONSTERS` | 27 | 45 | 63 行 / 27 只 |
| `SKILLS` | 25 | 40 | 59 行 / 40 个 |
| `MAPS` | 3 | 5 | 15 行 / 5 图 |
| `WEAPON_TYPES` | 13 | 13 | 19 行 |
| `ARMOR_TIERS_BY_TYPE` | 3×3 | 3×4 | 21 行 |
| `AFFIX_POOL` | 15 | 15 | 19 行 |
| `SETS` / `BOSS_DROPS` / `FLASK_*` / `SHARD_TYPES` / `FORGE_RECIPES` / `ORIGINS` / `MONSTER_SKILLS` | — | — | ~120 行 |
| **合计** | | | **约 320 → 本作约 600 行** |

> **优化这 600 行的编辑体验，比优化任何一处代码性能的收益都大。**

### 1.2 前作的问题（实测）

| # | 问题 | 证据 |
|---|---|---|
| **Q1** | **数据表里混着逻辑** | `mkMon()` L1733 是个函数，却位于数据区正中间。`MON_BODIES` / `MON_FEATURES`（L1515-1721，**219 行**）是 SVG 生成函数，也在数据区 |
| **Q2** | **没有字段契约** | `MONSTERS` 的字段（`hp/atk/def/spd/crit/emoji/art/elite/boss/skills`）**没有任何注释说明哪些必填、取值范围、单位**。填表者只能靠抄上一行 |
| **Q3** | **填错无提示** | 把 `art.body` 写成一个不存在的枚举 → `MON_BODIES[a.body]` 返回 `undefined` → L1725 有 `||MON_BODIES.beast` 兜底 → **静默显示成一只野兽，没有任何报错**。这是最恶劣的一类失败 |
| **Q4** | **无法批量校验** | 45 只怪物中有没有漏填 `spd` 的？没办法一次性知道。`mkMon()` 的 `Object.assign` 默认值（L1733）**掩盖了漏填** |
| **Q5** | **数据表与数据表之间的引用无校验** | `MAPS[i].pool` 里写了一个 `MONSTERS` 中不存在的 key → 运行到那张图才 crash。`SKILLS` 的 `weapons` 数组引用 `WEAPON_TYPES` 的 key，同理 |
| **Q6** | **数据表不冻结** | 运行时任何代码都可以改 `MONSTERS.xxx.hp`。前作 `applyCompat` 甚至真的会改装备的 `name` 字段 |

### 1.3 目标

> **让"填表"变成一项不需要理解代码、不需要打开控制台、填错能在 3 秒内被告知具体位置的工作。**

---

## 2. 决策

> ## 采用 **五条约定 + 一个启动期校验器**。
> 核心口号：**"填表只改全大写标识符的内容；填错，启动时控制台告诉你哪张表哪一行。"**

---

### 约定 1 · 物理隔离：§1 数据表章是"只读区"

`01-main-architecture.md` §2.4 定义的章节体系中，**§1 DATA 是一个封闭区域**：

```
/* ################################################################
   §1  数据表（只读）  DATA
   ────────────────────────────────────────────────────────────────
   🔴 本章规则：
      · 只允许字面量。禁止 function / G. / Math.random() / if
      · 所有表以 Object.freeze() 结尾
      · 每张表前必须有「字段契约」注释块
      · 填表工作只在本章内进行，不得越界
   ################################################################ */
```

**校验方式（可执行）**：本章范围内 `grep -c "function\|G\.\|Math\.random"` 必须为 **0**。

**需要从前作数据区迁出的内容**：

| 内容 | 前作位置 | 迁往 |
|---|---|---|
| `mkMon()` 工厂函数 | L1733 | **§2 生成器层** |
| `MON_BODIES` / `MON_FEATURES`（219 行 SVG 函数） | L1515-1721 | **§1.7 美术资产**（独立子章，**归美术总监维护，填表者不碰**） |
| `slotIconSVG` / `svgIcon` / `armorIconSVG` / `itemBadgeSVG` 等图标函数 | L1066-1140 | §1.7 |
| `mainAffixStat()` / `equipBaseName()` / `equipName()` | L1188-1220 | **§2 生成器层** |
| `skillWeaponOk()` / `weaponsLabel()` / `auraBonuses()` | L1469-1489 | **§3 战斗层** |
| `genFlask()` / `flaskAffix()` / `flaskHas()` | L1885-1917 | **§2 生成器层** |

> 📌 §1.7 美术资产是**特意分出来的**：它形式上是数据（枚举驱动的 SVG），但实质是美术产出物，与怪物数值表的维护者不同。**不要把它和 `MONSTERS` 混在一起**，否则填数值的人会被 219 行 SVG 淹没。

---

### 约定 2 · 每张表必须有「字段契约」注释块

这是解决 Q2 的核心。**格式固定，可被人读也可被校验器解析**：

```
/* ==================== 1.4 怪物表 MONSTERS ====================
 * 字段契约  ★=必填
 * ────────────────────────────────────────────────────────────
 * ★ name    string          显示名
 * ★ hp      int   [30,9999] 基础生命（会被 enemyUnit 按 tier 缩放）
 * ★ atk     int   [5,999]   基础攻击
 *   def     int   [0,999]   基础防御          默认 0
 *   spd     int   [10,80]   速度（ATB 充能率） 默认 30
 *   crit    float [0,1]     暴击率（小数！不是百分数） 默认 0.05
 * ★ art     object          程序化立绘参数
 *   art.body    enum ⟨MON_BODIES 的键⟩   ★  体型
 *   art.feature enum ⟨MON_FEATURES 的键⟩    特征   默认 'none'
 *   art.c1/c2/eye  '#RRGGBB'                     默认见 mkMon
 *   elite   bool            精英标记          默认 false
 *   boss    bool            BOSS 标记         默认 false
 *   skills  array⟨MONSTER_SKILLS 的键⟩       默认 []
 * ────────────────────────────────────────────────────────────
 * 引用关系：art.body → §1.7 MON_BODIES ｜ skills → §1.4b MONSTER_SKILLS
 * 被引用：  §1.5 MAPS.pool / MAPS.elite / MAPS.boss 用本表的键
 * 族群分组：污染兽 / 人型 / 亡灵 / 构装 / 秘术（见 GDD 11）
 * ============================================================ */
```

| 契约元素 | 作用 |
|---|---|
| `★` 必填标记 | 填表者一眼看出最少要写什么 |
| `[min,max]` 区间 | 校验器可解析，也让填表者知道量级 |
| `⟨表名 的键⟩` | 声明跨表引用，校验器据此做引用完整性检查（解决 Q5） |
| **「引用关系 / 被引用」两行** | 🔴 **最重要**。改一张表前，先看它被谁引用。这一行能避免"改了 `MONSTERS` 的 key，忘了改 `MAPS.pool`" |
| 「暴击率（小数！不是百分数）」这类括注 | 单位歧义是填表最高频的错误 |

> 📌 **契约块本身就是给填表者看的文档**。它就在数据表正上方，不需要跳到另一个文件。这是单文件架构少有的优势之一。

### 约定 3 · 表内行格式统一，一条记录一行

```
const MONSTERS = {
/* key              name       hp   atk  def  spd  crit  art                                   flags */
  moss_hound     : {name:'苔癣猎犬',   hp:120, atk:18, def:4,  spd:34, crit:.05, art:{body:'beast',  c1:'#6b7a5a', c2:'#3e4a30', eye:'#ffd24a'}},
  writ_husk      : {name:'空文躯壳',   hp:180, atk:22, def:9,  spd:26, crit:.05, art:{body:'husk',   c1:'#8a7f6a', c2:'#4a4238', eye:'#c8ff6a'}},
  seal_golem     : {name:'封印构装',   hp:420, atk:38, def:22, spd:18, crit:.08, art:{body:'golem',  c1:'#7a7f8a', c2:'#3a3f48', eye:'#5ad6ff'}, elite:true},
};
Object.freeze(MONSTERS);
```

| 规则 | 理由 |
|---|---|
| **一条记录严格一行**，字段顺序与表头注释一致 | 可以像 Excel 一样**竖着扫一列**检查数值是否单调递增。这是纯文本环境下最接近电子表格的体验 |
| **表头注释行**（`/* key name hp atk ... */`）对齐 | 不需要数第几个字段 |
| **列对齐**（用空格补齐） | ⚠️ 这会让 diff 变噪。**权衡后仍然采纳**：填表频率远高于 diff 阅读频率 |
| ❌ **禁止跨行的嵌套对象** | 一旦某条记录占 5 行，竖向扫描就失效了。字段多到放不下一行时，说明该拆子表 |

> ⚠️ **对 `SKILLS` 的例外**：前作 `SKILLS` 每条已是一行（59 行/40 个），✅ 符合。
> ⚠️ **对 `MON_BODIES` 的例外**：它是 SVG 生成函数，天然多行，已按约定 1 迁至 §1.7，不适用本约定。

---

### 约定 4 · `Object.freeze()` 全部数据表

解决 Q6。每张表定义后立即 `Object.freeze()`。

| 收益 | 说明 |
|---|---|
| 严格模式下写入抛异常 | 把"逻辑层偷偷改了数据表"从**静默 bug** 变成**响亮崩溃** |
| 明确表达意图 | `freeze` 是给读代码的人看的"这是常量"信号 |

> ⚠️ **注意**：`Object.freeze` 是**浅冻结**。`MONSTERS.moss_hound.art.c1` 仍可改。
> 需要一个 `deepFreeze()` 递归工具（约 8 行），在 §1 章末统一对所有表执行一次。
> ⚠️ 且必须确认：`enemyUnit()` L2454 是**复制**怪物定义到新对象（`const u={...}`），不是直接改定义 —— ✅ 我已复核，它构造新对象，冻结安全。

---

### 约定 5 · 命名编码"能不能改"

（与 `01-main-architecture.md` §2.4 规则 4 一致，此处复述其对填表的意义）

| 形态 | 填表者可否修改 |
|---|---|
| `全大写_下划线` 的**内容** | ✅ **可以** |
| `全大写_下划线` 的**键名** | ⚠️ **可以，但必须同步检查"被引用"那一行列出的所有位置** |
| 其他一切 | ❌ **不可以** |

> ✅ 这条把"填表工作的边界"压缩成了**一句可以贴在显示器上的话**。

### 🔴 核心机制 · `validateData()` 启动期校验器

这是解决 Q3/Q4/Q5 的关键，也是本 ADR 唯一需要写代码的部分（约 **60 行**）。

#### 运行时机

```
页面加载 → 数据表定义完毕 → if (DEV_MODE) validateData() → 正常启动
```

`DEV_MODE` 判定：`location.protocol==='file:' || location.hostname==='localhost' || location.search.includes('dev')`
> 📌 发布版给玩家时它不跑，零性能开销；但**开发者双击本地文件时它总是跑**——这正是我们要的。

#### 校验内容

| # | 检查 | 解决 | 输出示例 |
|---|---|---|---|
| V1 | **必填字段存在**（★ 项） | Q4 | `❌ MONSTERS.seal_golem 缺少必填字段 'atk'` |
| V2 | **类型正确** | Q2 | `❌ SKILLS.rite_of_seal.cd 应为 int，实际是 string "3"` |
| V3 | **数值在区间内** | Q2 | `⚠️ MONSTERS.void_wraith.crit = 5 超出 [0,1]（是不是把百分数当小数填了？）` |
| V4 | **跨表引用完整性** | Q5 | `❌ MAPS[2].pool 引用了不存在的怪物 'moss_hund'（是不是想写 'moss_hound'？）` |
| V5 | **枚举值合法** | Q3 | `❌ MONSTERS.chief_scribe.art.body = 'humanoid' 不在 MON_BODIES 中。可用值: beast/husk/golem/...` |
| V6 | **反向引用覆盖** | — | `⚠️ MONSTERS.old_beast 未被任何 MAPS 引用（孤儿数据，是否忘了加入怪物池？）` |
| V7 | **键名拼写相似度提示** | Q5 | 引用失败时用编辑距离给出最接近的候选（V4 的"是不是想写"） |

#### 输出形态

```
console.group('📋 数据表校验')
  ❌ 3 个错误 · ⚠️ 2 个警告 · ✅ 14 张表 / 187 条记录
  ────────────────────────────────────────────────
  ❌ MONSTERS.seal_golem       缺少必填字段 'atk'
  ❌ MAPS[2].pool[3]           引用了不存在的怪物 'moss_hund' → 是不是 'moss_hound'？
  ❌ SKILLS.rite_of_seal.weapons[1]  引用了不存在的武器类型 'grimore' → 是不是 'grimoire'？
  ⚠️ MONSTERS.void_wraith.crit = 5   超出 [0,1]（百分数写成小数了？）
  ⚠️ MONSTERS.old_beast        孤儿数据，未被任何 MAPS 引用
console.groupEnd()
```

**并在页面顶部显示一条红色横幅**「⚠️ 数据表校验失败（3 项），详见控制台」——因为填表者不一定会主动开控制台。

#### 🔴 V5 的重要性

前作 `MON_BODIES[a.body] || MON_BODIES.beast`（L1725）的**兜底默认值是个陷阱**：它让"填错枚举"变成"静默显示成野兽"。
> ✅ **决策：保留运行时兜底**（避免玩家侧崩溃），**但由 V5 在开发期把它揪出来**。
> 这是"生产环境宽容、开发环境严格"的标准做法，两全其美。

## 3. 后果

### 3.1 ✅ 正面

| # | 收益 | 量化 |
|---|---|---|
| 1 | 填表工作**不需要理解逻辑代码** | 79% 的工作被限定在一个封闭章节内 |
| 2 | 填错的定位时间从"运行到那张图才发现"降到**启动即知，精确到字段** | Q3/Q4/Q5 全解 |
| 3 | 跨表引用错误（改 key 忘了改引用）被自动捕获 | 这是重命名 27→45 只怪物时**最可能犯的错** |
| 4 | 字段契约块 = 就地文档，不需要另开 wiki | 契合单文件精神 |
| 5 | 表格化行格式支持"竖向扫数值曲线" | 数值平衡时（Phase 4）价值极高 |
| 6 | `deepFreeze` 把数据污染从静默 bug 变响亮崩溃 | |

### 3.2 ❌ 负面 / 成本

| # | 代价 | 缓解 |
|---|---|---|
| 1 | `validateData()` 约 **60 行** + `deepFreeze` 8 行 | 一次性；且它替代的是"每次填错花 20 分钟排查"，1-2 次就回本 |
| 2 | 契约注释块本身约 **80 行**（14 张表 × 平均 6 行） | 可读性收益远超行数成本 |
| 3 | **列对齐让 git diff 变噪**（改一个字段宽度可能导致整表重排） | 🟡 接受。规定：**只在新增字段时重排一次，日常改数值不动对齐** |
| 4 | 契约注释**可能与实际字段脱节**（改了字段忘了改注释） | ⚠️ **真实风险，无完美解**。缓解：`validateData` 直接**从契约注释解析规则**（而非另写一份规则），使二者天然同步 —— 见下 |
| 5 | 校验器需要一份"规则表"，可能与契约注释重复 | 🔴 **关键设计**：让校验规则**就是**契约的机器可读版本，写在契约块正下方的 `MONSTERS_SCHEMA = {...}` 常量里，两者相邻、一起改。避免两地维护 |

> ⚠️ **代价 4/5 是本 ADR 最脆弱的一环**，我如实标注。折中方案是「契约注释给人读 + 相邻的 `_SCHEMA` 常量给机器读」，二者物理相邻降低脱节概率，但**不能杜绝**。
> 若未来发现脱节频繁，升级路径是：只保留 `_SCHEMA` 常量，由一个小函数把它**渲染成**控制台可打印的契约表 —— 单一真相源。**MVP 不做，记录为观察项。**

## 4. 备选方案

| 方案 | 描述 | 否决理由 |
|---|---|---|
| **A. 沿用前作现状** | 数据表散落，无契约，无校验 | ❌ Q1-Q6 全部保留。在 79% 工作量都是填表的项目里，这是最大的一处系统性浪费 |
| **B. 数据表外置为 JSON 文件** | `data/monsters.json`，游戏 `fetch` 加载 | 🔴 **致命**：`file://` 协议下 `fetch` 被 CORS 拦截，**双击打开直接失效**。这是 ADR-001 明确要保护的分发方式。<br>🟡 变通：内联 `<script type="application/json" id="monsters">`——可行，但① JSON 不支持注释，**契约块无处安放**（这恰恰是本 ADR 的核心价值）② JSON 不能写 `.05` 只能写 `0.05`，不能写尾逗号，编辑体验更差 |
| **C. 数据表外置为独立 CSV + 构建期内联** | 用 Excel 填表，构建时转成 JS | ❌ 引入构建链，违反 ADR-001。<br>🟡 但**思路值得吸收**：约定 3 的"表格化行格式"就是在纯文本里模拟 CSV 的编辑体验 |
| **D. 用 TypeScript 定义数据表类型** | `.ts` + `tsc` 编译 | ❌ 引入构建链。<br>✅ **部分采纳**：`validateData()` 就是"运行时的 tsc"，把类型检查从编译期挪到启动期 |
| **E. 不做校验器，只做契约注释** | 只写文档不写代码 | ❌ 注释无法阻止错误。Q3（枚举填错静默兜底）**只能靠代码检出**。校验器 60 行，是本 ADR 性价比最高的部分，不能省 |
| **F. 引入 Zod / Yup 做 schema 校验** | 成熟库 | ❌ 违反零依赖。且我们只需要 7 类检查，手写 60 行足够，引库要内联几十 KB |

```

 填表规则速查  ——  §1 数据表章
════════════════════════════════════════════════════════════
 ✅ 你可以改：全大写常量里的内容
 ⚠️ 改键名前：先看该表契约块的「被引用」那一行

```
